# MiniMind Agentic RL 改动总览与调用链说明

这份文档用于说明本轮 Agentic RL 改造到底完成了什么、后续还需要做什么、每个新增或修改文件的职责，以及这些文件在真实运行时如何串起来。

---

# 1. 总体完成了什么

本轮改造的核心目标是把 MiniMind 从一个“可以跑工具调用 demo 的小模型项目”，升级成一个初步完整的 **Tool-Use Agentic RL 实验闭环**。

改造前，项目中和 Agent 相关的逻辑比较分散：

```text
scripts/eval_toolcall.py
  有一套工具定义、工具执行、解析和兜底逻辑

trainer/train_agent.py
  又有一套 mock 工具、parse_tool_calls、execute_tool、reward 逻辑

dataset/lm_dataset.py
  有 AgentRLDataset，但 SFTDataset 没有真正把 tools schema 传进 chat template
```

改造后，核心逻辑被统一到 `agent/` 目录：

```text
agent/tools.py
agent/parser.py
agent/tool_env.py
agent/trajectory.py
agent/reward.py
agent/masks.py
```

现在 demo、eval、training 都可以复用同一套：

```text
工具定义
tool_call 解析
工具执行环境
轨迹记录
reward 分解
failure taxonomy
```

也就是说，项目已经具备以下能力：

```text
1. 统一工具注册和执行
2. 统一 <tool_call> 解析
3. raw / guarded 两种 Agent 运行模式
4. 完整 trajectory 记录
5. trajectory-level reward 分解
6. failure taxonomy
7. 批量 tool-use eval
8. tool-call SFT 数据生成
9. Agent RL 数据生成
10. train_agent.py 接入 ToolUseEnv 和 compute_total_reward
11. 训练日志增加 reward breakdown、KL、clip_frac、tool_count、loop/malformed 等稳定性指标
12. response mask 辅助检查，避免误训练 tool_response
```

# 2. 总体还需要做什么

当前代码已经完成了 Agentic RL 的工程骨架，但还没有完成完整实验闭环。后续工作主要分三类：训练、数据集扩展、继续补强代码。

## 2.1 需要训练

第一步要跑 baseline：

```bash
python evals/run_tool_eval.py --weight full_sft --mode raw --device cuda
python evals/run_tool_eval.py --weight full_sft --mode guarded --device cuda
```

这一步用于得到 `full_sft_768.pth` 的基础能力：

```text
valid_rate
tool_acc
args_acc
obs_use_acc
answer_acc
loop_rate
malformed_rate
unfinished_rate
```

第二步做 tool-call SFT：

```bash
cd trainer
python train_full_sft.py ^
  --from_weight full_sft ^
  --save_weight tool_sft ^
  --data_path ../dataset/tool_sft_small.jsonl ^
  --epochs 1 ^
  --batch_size 4
```

目标是提升：

```text
valid_rate
tool_acc
args_acc
```

第三步做 Agent RL / GRPO / RLVR：

```bash
cd trainer
python train_agent.py ^
  --rollout_engine torch ^
  --from_weight tool_sft ^
  --save_weight agent_tool ^
  --data_path ../dataset/agent_rl_tooluse.jsonl ^
  --batch_size 1 ^
  --num_generations 2
```

目标是提升：

```text
obs_use_acc
answer_acc
loop_rate
unfinished_rate
```

训练完成后，对三类模型都跑同一套 eval：

```text
full_sft
tool_sft
agent_tool
```

并分别比较：

```text
raw
guarded
```

最终应该形成一张表：

| Model | Mode | valid | tool_acc | args_acc | obs_use | answer_acc | loop_rate | malformed |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| full_sft | raw | | | | | | | |
| full_sft | guarded | | | | | | | |
| tool_sft | raw | | | | | | | |
| tool_sft | guarded | | | | | | | |
| agent_tool | raw | | | | | | | |
| agent_tool | guarded | | | | | | | |

## 3.5 `agent/tool_env.py`

作用：

```text
统一 Agent 工具环境，是 demo、eval、training 的共同运行时。
```

核心功能：

```text

   初始化任务、prompt、tools、messages、trajectory。

2. ToolUseEnv.step(model_output)
   接收模型输出，判断是 tool_call、final answer 还是 parse error。

3. _handle_tool_call()
   执行工具、追加 tool message、记录 trajectory。

   处理最终答案或 malformed tool_call。

5. loop 检测
   repeated tool call 在 guarded 模式会被阻断。

6. max_tool_calls 限制
   防止无限工具调用。

7. render_final_answer()
   guarded 模式下可根据工具历史生成兜底答案。
```

被谁调用：


# 4. 文件之间如何调用

下面按三条主线解释。

---

## 4.1 评测调用线

评测入口：

```text
evals/run_tool_eval.py
```

主要调用链：

```text
evals/tool_eval.jsonl
  -> run_tool_eval.py 读取 eval item
  -> init_local_model() 加载模型
  -> ToolUseEnv.reset(item)
  -> tokenizer.apply_chat_template(
       env.get_messages(),
       tools=env.get_tool_schemas()
     )
  -> model.generate()
  -> ToolUseEnv.step(model_output)
       -> parser.parse_first_tool_call()
       -> tools.execute_tool_call()
       -> trajectory 记录 step
  -> 如果还有工具调用，继续下一轮 generate
  -> env.get_trajectory()
  -> reward.compute_total_reward(trajectory, item)
  -> 保存 summary / failures / trajectories
```

核心关系：

```text
run_tool_eval.py 不直接解析 tool_call，也不直接执行工具。
它只负责模型推理和批量评测流程。

真正的 Agent 环境逻辑都在 ToolUseEnv。
```

---

## 4.2 交互 demo 调用线

入口：

```text
scripts/eval_toolcall.py
```

主要调用链：

```text
用户输入 prompt
  -> ToolUseEnv.reset({"prompt": prompt, "tools": tools})
  -> generate(model, tokenizer, env.get_messages(), env.get_tool_schemas())
  -> ToolUseEnv.step(content)
       -> parse tool_call
       -> execute tool
       -> append tool_response
  -> 如果 done，打印 env.render_final_answer()
```

核心关系：

```text
eval_toolcall.py 是展示层。
ToolUseEnv 是运行时。
agent/tools.py 是工具层。
agent/parser.py 是解析层。
```

## 4.3 RL 训练调用线

入口：

```text
trainer/train_agent.py
```

数据：

```text
dataset/agent_rl_tooluse.jsonl
```

主要调用链：

```text
AgentRLDataset.__getitem__()
  -> 返回 messages, tools, gt, task

DataLoader
  -> collate_fn()
  -> batch: messages_batch, tools_batch, gt_batch, tasks_batch

rl_train_epoch()
  -> rollout_batch()
      -> rollout_single()
          -> ToolUseEnv.reset()
          -> tokenizer.apply_chat_template()
          -> rollout_engine.rollout()
          -> ToolUseEnv.step()
          -> 记录 response_ids / response_mask / old_logps / trajectory

  -> 打包 input_ids / completion_mask / old_per_token_logps
  -> 当前 model 重新算 per_token_logps
  -> ref_model 算 ref_per_token_logps
  -> calculate_rewards()
      -> compute_total_reward(trajectory, task)
      -> aggregate_reward_infos()
  -> group rewards -> advantages
  -> GRPO/CISPO loss
  -> optimizer.step()
```

这里最关键的设计是：

```text
模型生成的 assistant token:
  response_mask = 1

环境生成的 tool_response token:
  response_mask = 0
```

也就是说：

```text
模型 action 参与策略梯度。
环境 observation 不参与策略梯度。
```

这正是 Agentic RL 和普通 SFT 的关键区别之一。

# 5. 为了实现新增功能，一条主要调用线是什么

最核心的一条调用线是 **Agent RL 训练线**：

```text
dataset/agent_rl_tooluse.jsonl
  -> AgentRLDataset
  -> trainer/train_agent.py
  -> rollout_single()
  -> ToolUseEnv.step()
  -> parser.parse_first_tool_call()
  -> tools.execute_tool_call()
  -> trajectory.ToolTrajectory
  -> reward.compute_total_reward()
  -> GRPO/CISPO loss
  -> optimizer.step()
```

用更直观的方式看：

```text
1. 数据集给出任务：
   prompt + tools + expected_answer

2. 模型生成动作：
   <tool_call>{"name": "...", "arguments": {...}}</tool_call>

3. ToolUseEnv 解析动作：
   parser.py 检查 JSON、工具名、参数

4. ToolUseEnv 执行动作：
   tools.py 调用真实工具函数

5. ToolUseEnv 返回 observation：
   {"result": 9472}

6. 模型继续生成 final answer：
   256*37 = 9472

7. trajectory.py 记录完整过程：
   user -> assistant_tool_call -> tool_observation -> assistant_final

8. reward.py 给整条轨迹打分：
   tool_name 对不对
   args 对不对
   是否用了 observation
   final answer 对不对
   是否 loop
   是否 malformed

9. train_agent.py 用 reward 训练：
   多条 trajectory 组内标准化
   得到 advantage
   计算 GRPO/CISPO loss
   更新模型
```

这条线完成了真正的 Agentic RL 闭环。
